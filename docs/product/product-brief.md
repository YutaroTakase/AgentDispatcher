# AgentDispatcher — プロダクト概要 v0.1

## 1. プロダクトビジョン

AgentDispatcherは、GitHub Issueを起点としてAI開発作業者へ作業を割り当て、複数プロジェクトの実行を一元管理するためのセルフホスト型Webアプリケーションである。

特定のリポジトリや開発フローへ依存せず、プロジェクトごとのIssue取得条件と推論モデルの選択規則を設定するだけで再利用できることを重視する。

## 2. 対象利用者

初期対象は、1台の開発PC上で複数リポジトリをAI開発作業者に処理させたい個人開発者とする。

組織向けSaaSや複数利用者による共同利用は初期対象としない。

## 3. 解決する課題

AI開発作業者を複数プロジェクトで運用すると、次の管理がプロジェクトごとに重複する。

- 実行対象Issueの選択
- 使用する推論モデルと推論レベルの選択
- 同一Issueの二重実行防止
- 実行環境と作業ツリーの管理
- 作業者の起動、停止、結果確認
- 実行履歴とログの保持、削除
- GitHubとCodexの利用可否確認

AgentDispatcherはこれらを共通の管理基盤へ集約する。

## 4. MVPで実現すること

- 複数のGitHubリポジトリをプロジェクトとして登録できる。
- プロジェクトごとにIssue取得条件を設定できる。
- プロジェクトごとに推論モデルと推論レベルの選択規則を設定できる。
- 対象IssueごとにCodexを起動できる。
- 実行中の状態、結果、ログ、失敗理由をWeb画面から確認できる。
- 保存期間をプロジェクトごとに設定し、不要な履歴と実行資産を自動整理できる。
- GitHubやCodexを含む実行環境の状態を確認できる。

詳細な振る舞いは[プロダクト要件](product-requirements.md)を正本とする。

## 5. MVPで提供しないこと

- ChatGPTの会話そのものの管理
- ChatGPTのスケジュール済みタスクの管理
- OpenAI APIを利用した独自AI実行基盤
- PM、レビュー担当、設計担当など複数AIの連携制御
- GitHub CIの包括的な操作
- Pull Requestの自動マージ
- 別PC上の実行作業者
- Windows上で直接動作する実行作業者
- 複数利用者向けの権限管理
- SaaSとしての提供
- 課金、ライセンス管理
- 推論モデル利用量の正確な金額換算

## 6. 成功条件

対応環境へAgentDispatcherを導入し、Web画面からプロジェクトを登録した後、対象GitHub Issueを検出してCodexを起動し、その結果を実行履歴画面で確認できることをMVPの完成条件とする。
